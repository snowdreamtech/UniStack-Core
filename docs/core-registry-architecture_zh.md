# 核心库架构 (Core Registry Architecture)

本文档定义了 UniStack 核心库（注册中心）的标准架构和运营模型。

## 1. 概述

UniStack 社区生态系统采用了一种混合架构：**以中心化的 PR 驱动为主，以分布式的自定义源（Custom Registry）为辅**。该模型在确保安全性、高性能和生态系统快速增长的同时，也能满足企业级的私有化部署需求。

## 2. 注册中心分层

整个生态系统分为三个截然不同的层级：

### 2.1 核心库 (`unistack-core`)
- **维护者**: 官方 UniStack 团队。
- **特征**: 经过极其严格的审计，高度安全，并提供完全的向后兼容保证。
- **命名空间**: 独占全局、无前缀的根命名空间（例如：`nginx`）。

### 2.2 社区库 (`unistack-community`)
- **维护者**: 社区驱动，由官方维护者和自动化机器系统共同审查。
- **特征**: 一个中心化的单一代码仓库 (Monorepo)，开发者通过向其提交 Pull Requests (PRs) 来新增或更新包。
- **命名空间**: **必须 (MUST)** 包含作者或组织的命名空间前缀（例如：`snowdreamtech/nginx`）。

### 2.3 自定义源 (Custom Registries / Taps)
- **维护者**: 个人开发者或企业组织。
- **特征**: 完全去中心化。用户通过 CLI 工具手动添加独立的注册中心 URL（例如：`unistack registry add my-company https://...`）。
- **用例**: 专门为企业内部私有工具、敏感代码或不适宜对外公开的闭源软件提供独立的安装渠道。

## 3. 存储与分发 (GitOps 模型)

该架构在源代码和二进制分发环节实施了极度严格的物理分离。

- **唯一的真相源 (GitHub)**: GitHub 仓库（`unistack-community` 和 `unistack-core`）**仅**托管纯文本配置文件（例如 `package.yml`）。任何二进制文件（`.tar.gz`, `.uspkg`）都绝不会被提交到代码仓库中，这保证了 Git 历史记录的轻量和克隆速度。
- **制品分发 (CDN)**: 当 PR 被合并后，自动化 CI 流水线会将源代码打包为二进制包，更新总索引记录（`packages.db`），并将这些最终制品推送到 CDN 或静态对象存储（例如 Cloudflare R2, AWS S3）。
- **客户端获取**: UniStack CLI 客户端直接从全球加速的高速 CDN 下载索引和软件包，拉取过程完全绕过 GitHub 源码仓库。

## 4. 安全与质量管控

为了防止生态系统遭到污染（如包名抢注、依赖混淆攻击和恶意代码执行），系统严格执行以下安全措施：

### 4.1 严格的命名空间管控 (Strict Namespacing)
严禁任何社区包试图使用全局根命名空间。任何试图提交无前缀包（意图抢注核心包名）的 PR 都会在最初始的校验阶段被直接拦截并拒绝。

### 4.2 自动化的沙盒验证 (Automated Sandbox Validation)
向 `unistack-community` 提交的每个 PR 在进入人工代码审查前，都必须通过自动化 CI/CD 流水线。CI 流水线将执行：
1. 验证 `package.yml` 的格式正确性。
2. 确保下载 URL 强制使用 HTTPS 并且文件校验和（Checksum）完全匹配。
3. 在隔离的一次性 Docker 容器中执行沙盒安装测试，以主动侦测其中是否夹带恶意挖掘脚本或试图篡改系统关键目录的行为。

### 4.3 贡献者许可协议 (CLA)
为了确保商业分发的合规性和法律安全性，所有外部代码贡献者**必须 (MUST)** 在其 PR 合并前，通过自动化服务平台（例如 CLA Assistant）签署贡献者许可协议 (CLA)。

## 5. 客户端解析策略

UniStack CLI 客户端在设计上支持同时配置多个仓库源。为了从根本上杜绝“依赖混淆攻击”（即恶意的社区包试图利用更高的版本号来非法覆盖官方核心包），客户端在底层实现了极为严格的、基于优先级的防线机制：

1. **最高优先级**: 核心库 `unistack-core`
2. **中等优先级**: 社区库 `unistack-community`
3. **最低优先级**: 自定义源 Custom Registries (除非用户手动调整覆盖)

当用户执行安装命令且出现包名冲突时，客户端将严格解析并返回具有最高优先级源中的包，确保核心基础设施绝对不会被篡改或覆盖。
